## Streaming Responses

Relay streams AI responses in real time. As the AI generates text, the Telegram message is progressively edited so you see output as it's produced.

1. You send a message
2. The bot sends a "thinking" indicator
3. As text arrives, the message is edited in place
4. When complete, the final message is sent

Messages are updated roughly every second to stay within Telegram rate limits. Long responses are automatically split into multiple messages (4096-character limit). Tool use indicators like "Reading file..." or "Running command..." appear during processing.

Streaming is enabled by default. To disable:

```env
STREAMING=false
```

## File Attachments

When the AI generates files, takes screenshots, or creates artifacts, they are sent as Telegram attachments. This is available with the OpenCode provider only — Claude and Codex do not support file output.

Supported types:
- Images (`png`, `jpeg`, etc.) — sent as Telegram photos
- All other files — sent as documents with the original filename

---

## Voice Messages

Send voice notes to the bot and they'll be transcribed and processed as text input. Configure at least one speech-to-text provider:

```env
GROQ_API_KEY=gsk_...
OPENAI_API_KEY=sk-...
ASSEMBLYAI_API_KEY=...
```

Provider priority (when `STT_PROVIDER=auto`): Groq > OpenAI > AssemblyAI.

---

## Photo Input

Send photos for analysis by vision-capable models. Add a caption to ask specific questions (e.g., "What's wrong with this UI?"). Without a caption, the AI will describe the image. Check `/models` for vision badges.

---

## File Input

Send files as attachments. Text files (`.txt`, `.md`, `.js`, `.py`, `.json`, `.yaml`, `.toml`, `.xml`, `.csv`, `.html`, `.css`, etc.) are read and embedded directly in the message to the AI. Binary files are referenced by name only.

Text messages have a 32,000-character limit. For larger content, send as a file attachment.

## MCP Servers

MCP (Model Context Protocol) servers extend the AI's capabilities with additional tools. Supported by OpenCode (full API) and Claude (persisted to disk). Not available with Codex.

### Local servers

Run as subprocesses on the same machine. Examples:

- `/mcp add memory local npx -y @modelcontextprotocol/server-memory`
- `/mcp add browser local npx -y @anthropic-ai/mcp-server-puppeteer`

### Remote servers

Connect via URL: `/mcp add api remote https://mcp.example.com/sse`

## Model Selection

Switch between AI models at runtime. `/models` lists all configured models with capability badges: `[reasoning]`, `[vision]`, `[active]`.

Switch models with `/model sonnet`, `/model deepseek`, or use a full path like `/model anthropic/claude-sonnet-4-20250514`.

Provider behavior:
- OpenCode — lists all models from all configured providers
- Claude — fetches available models from the Anthropic API
- Codex — fetches available models from the OpenAI API

## System Prompt

Customize the AI's behavior with a system prompt file. The bot loads `skill.md` from the project root by default. Change the path with:

```env
SYSTEM_PROMPT_FILE=prompts/my-prompt.md
```

The file is watched for changes and reloaded automatically. Force reload with `/system reload`.

---

## Session Management

Sessions keep conversations organized. Each session maintains its own message history.

Create sessions with `/new` or `/new Refactoring auth module`. Fork a session with `/fork` or `/fork msg_abc123`.

---

## State Persistence

Relay persists critical state to disk so it survives restarts:

- `.relay/session.json` — Current session ID and selected model
- `.relay/claude-mcp.json` — Claude MCP server configurations
- `.relay/codex-threads.json` — Codex thread ID mappings

State is written atomically (temp file + rename) to prevent corruption.

---

## Webhook Deployment

For production, run Relay in webhook mode instead of long-polling.

```env
BOT_MODE=webhook
WEBHOOK_URL=https://your-server.com/bot
WEBHOOK_PORT=3000
WEBHOOK_SECRET=your-random-secret
```

Benefits: lower latency, reduced resource usage, better for containerized deployments.
